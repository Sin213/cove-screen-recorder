## Root cause (from prior diagnostic pass)

`RetryShmAfterDmaBufFailure` was reconnecting with the primary nonzero-rate pod  
(`build_format_enum_pod`, VideoFramerate min=1/1). KDE Wayland proposes 0/1  
(variable rate) during format negotiation; 0/1 < 1/1 causes an empty intersection  
→ "no more input formats" stream error fires a second time  
→ second-fire guard triggers → `no-acceptable-buffer-type`.

The fix uses the legacy permissive pod (min=0/1) for the retry reconnect, which  
accepts the compositor's 0/1 proposal and allows format negotiation to succeed.
