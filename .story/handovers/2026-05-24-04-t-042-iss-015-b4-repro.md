## Root Cause

**The eviction policy checks `now_pts - segment.pts_start_90k > window_duration_90k`. Since each segment's PTS duration (~38.6s) exceeds the window (30s), the segment's start is already outside the window at the moment now_pts equals the segment's end. Every segment is immediately evictable upon commit.**

Under static-screen dedup conditions:
- Each segment accumulates ~38.6s of PTS before committing
- Window = 30s
- At commit time: segment.pts_end ≈ now_pts, so age = now_pts - pts_start ≈ 38.6s > 30s
- `evict_eligible` fires immediately, `trigger=age`, ring emptied
- Next save attempt always sees an empty committed ring

This explains T-039's observation: `segments_committed > 0` but pin always fails. The counter increments at commit time, but eviction fires before pin_snapshot can run.

**Note on T-039 hypothesis:** T-039 hypothesized that `duration_eligible=false` was the pin predicate gate. T-042 disproves this — the pin predicate is never reached because the committed ring is emptied by eviction first. The T-040 warn fires at the `inner.committed.is_empty()` guard, before any pin predicate check.

## Remediation Path (T-043)

T-043 created: fix `evict_eligible` to use an overlap check instead of start-age check. Proposed: evict segment only if `segment.pts_end < cutoff` (cutoff = now_pts - window_duration_90k). This keeps segments whose end is within the window, regardless of how old their start is. Affected file: `helper/src/segment/buffer.rs`, `evict_eligible` function.
