**FAIL** — three gating thresholds failed, all caused by display mode mismatch.

| Threshold | Observed | Required | Passed |
|---|---|---|---|
| capture cell matches declared (1920x1080) | 3840x2160 | 1920x1080 | **FAIL** |
| drop rate <= 0 | 0.5435 (54.4%) | <= 0 | **FAIL** |
| cadence mean in range [51.00..61.20] fps | 98.169 fps | 51.00..61.20 | **FAIL** |
| cadence spread ≤ 6.0 fps | 6.000 fps | ≤ 6.0 | PASS |
| diagnostics samples >= 1 | 60 | >= 1 | PASS |
| encoder.selected backend is nvenc | nvenc | nvenc | PASS |

**Root cause:** The display was running at 3840x2160@239.99 instead of the required 1920x1080@60. PipeWire negotiated a 3840x2160 capture stream (`sessionReady` format: `width: 3840, height: 2160, fps_num: 0, fps_den: 1`). The validator expected 1920x1080. All three failing thresholds (cell, drop rate, cadence) are downstream of this mismatch.

This is an **operator-side environment issue**, not a regression in the NVENC IDR fix or any source code change. The VAL-CAP-004 cadence/drop logic and source files were not modified in this rerun.

The drop rate of 54.4% and cadence of 98fps are consistent with a 3840x2160@240fps source being captured at the encoder's frame production rate (~98fps effective vs ~150fps raw at 240hz), rather than a 1920x1080@60fps source.
