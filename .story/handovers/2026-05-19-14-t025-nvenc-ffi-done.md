# T-025 / ISS-004 — NVENC FFI struct layout fixes complete

## What was done

`nvenc_one_frame_shm_encode_produces_fmp4_fragment` now passes.

Four `#[repr(C)]` struct layout bugs in `helper/src/encoder/backends/nvenc/mod.rs` were fixed against SDK 12.1:

### 1. NV_ENC_INITIALIZE_PARAMS — wrong GUIDs (fixed earlier session)
- `NV_ENC_CODEC_H264_GUID` and `NV_ENC_PRESET_P4_GUID` bytes were wrong. Confirmed via runtime queries. Error was `nvEncInitializeEncoder:12` (NV_ENC_ERR_UNSUPPORTED_PARAM) then `:8` (NV_ENC_ERR_INVALID_PARAM).

### 2. NV_ENC_PIC_PARAMS — three fields wrong (fixed this session)
- `codecPicParams: [u8; 256]` → `[u8; 1024]` (NV_ENC_CODEC_PIC_PARAMS union is `uint32_t reserved[256]` = 1024 bytes)
- `meHintCountsPerBlock: [u32; 2]` → `[u8; 32]` (NVENC_EXTERNAL_ME_HINT_COUNTS_PER_BLOCKTYPE[2] is 16 bytes each)
- Missing `bufferFmt: u32` between `completionEvent` and `pictureStruct` (added in SDK 12.x). Without it, driver read pictureStruct from offset 64 (our pictureType=0), and 0 is invalid for NV_ENC_PIC_STRUCT.
- Final struct size: 2832 bytes.

### 3. NV_ENC_LOCK_BITSTREAM — bit-fields packed wrong
- C SDK has `doNotWait:1 | ltrFrame:1 | getRCStats:1 | reservedBitFields:29` all in one `uint32_t`.
- Our Rust had 3 separate `u32` fields, adding 8 bytes before `outputBitstream`, making the pointer land at offset 16 instead of 8. Driver rejected with `:8` (NV_ENC_ERR_INVALID_PARAM).
- Fixed: collapsed to single `flags: u32`.
