## 3. Diagnostics Behavior Added

### `helper/src/export/mod.rs`

**`emit_export_failed` signature change:**
Added `diagnostics_path: &str` parameter (before `terminal_fired`). Uses it to populate `ExportFailedEvent.diagnostics_path` instead of always `String::new()`.

**Diagnostics file creation (in `run_export`):**
After `concat_input` is built and before ffmpeg spawn:
1. `diag_path = staging_dir/<export_id>.diagnostics.txt`
2. Preamble written to file:
   - `argv: ffmpeg -y -i <concat_input> -c copy -movflags +faststart -progress pipe:1 <tmp_path>`
   - For each concat input: `input <i>: <path> | exists=<bool> | size_bytes=<N or ?>`
   - Marker: `--- ffmpeg stderr ---`
3. File opened for appending — passed as `.stderr(stderr_stdio)` to ffmpeg
4. ffmpeg argv unchanged; ffmpeg stdout pipe and progress parser unchanged
5. `diag_path_str` passed to all `emit_export_failed` call sites after creation point

**Call sites:**
- `stream-copy-requires-reencode` (before diag file): passes `""`
- `staging-dir-unwritable` (before diag file): passes `""`
- All 18 remaining call sites (after diag file): pass `&diag_path_str`

**Diagnostics file is written/flushed before `export.failed` notification:**
- ffmpeg child holds the write fd; child exits before `emit_export_failed` is called
- After `child.wait()`, stderr writes are complete before `emit_export_failed`

### `validation/drivers.ts`

In `driveValExp001`, after writing `export-terminal-event.json`:
- If `terminalMethod === "export.failed"` and `diagnostics_path` is a non-empty string:
  - Check `fs.existsSync(diagSrc)`
  - If exists: `fs.copyFileSync(diagSrc, path.join(evidenceDir, "ffmpeg-diagnostics.txt"))`
- Entire block wrapped in try/catch — missing/unreadable diagnostics cannot crash or change verdict
- No pass/fail logic changed
