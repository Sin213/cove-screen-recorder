# T-034 ISS-014 XR24→NV12 Conversion Implementation

## Session Summary
Implemented the ISS-014 root cause fix: BT.709 limited-range XR24/AR24→NV12 conversion in `helper/src/encoder/backends/nvenc/mod.rs`, preventing deterministic vertical striping when PipeWire SHM fallback delivers packed BGRx frames to the NVENC backend.

## What Changed
Single file: `helper/src/encoder/backends/nvenc/mod.rs` (+347/-31 lines)

1. **DRM fourcc constants** — `DRM_FORMAT_XR24` (0x34325258), `DRM_FORMAT_AR24` (0x34325241), `DRM_FORMAT_NV12` (0x3231564E) as local module constants
2. **`convert_packed_bgra_to_nv12()`** — pure scalar BT.709 limited-range conversion function:
   - Y plane: per-pixel with `Y = 16 + ((47*R + 157*G + 16*B + 128) >> 8)`, clamped [16,235]
   - UV plane: 2×2 block averaging, interleaved NV12 write, clamped [16,240]
   - Bounds-checked source reads against `src_len`, padding with Y=16/U=128/V=128
3. **Format match in `push_frame()`** — replaces unconditional NV12 copy with:
   - XR24 → `convert_packed_bgra_to_nv12(has_alpha=false)`
   - AR24 → `convert_packed_bgra_to_nv12(has_alpha=true)`
   - `_` (NV12, P010) → original copy loops verbatim
4. **Logging** — `path="convert"|"copy"` field added to `[iss-014][encode-boundary]` diagnostics
5. **12 unit tests** — white/black/RGB primaries/stride padding/oversized enc/checkerboard averaging/truncated src/zero dims/fourcc constants

## Key Decisions
- Conversion is pure scalar (no SIMD/intrinsics) — correctness over performance for initial fix
- `DRM_FORMAT_NV12` is `#[cfg(test)]` only since the runtime match uses `_` arm for all non-XR24/AR24 formats
- `#[allow(clippy::too_many_arguments)]` on conversion function (signature matches task spec)
- UV rounding: BT.709 integer coefficients produce U=127 for pure white (±1 from neutral 128) — tests use tolerance
