Exit code 183 = `AVERROR_INVALIDDATA` in ffmpeg/libavutil. This error occurs when ffmpeg cannot parse a valid header from the byte stream presented by the `concat:` protocol.

---

## 17. Root-Cause Progression

**Rerun 18 root cause:** `init.mp4` was missing from segment dir → ffmpeg exit 254 ("No such file or directory")

**Rerun 19 new root cause:** `init.mp4` now persisted (664 bytes), all inputs exist, but the `concat:` byte-concatenation protocol cannot parse fMP4 header → ffmpeg exit 183 ("Invalid data found when processing input")

The `concat:` protocol is documented for raw MPEG-TS / byte-level file concatenation. For fragmented MP4 (fMP4) with a separate init segment and media fragments, the correct approaches are:
1. **`concat` demuxer** with a text manifest (`-f concat -i list.txt`) — properly demuxes each input as a separate container
2. **Byte-level cat** of `init.mp4 + all_fragments.mp4` into a single blob → pipe to ffmpeg as a single fMP4 input

The `concat:` URL protocol used here is structurally wrong for fMP4. This is defect #2 identified in rerun 18's handover. Now confirmed by ffmpeg stderr.
