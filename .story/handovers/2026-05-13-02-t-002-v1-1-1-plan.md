### Sub-item A — Replay keybind shown with other keybinds (Issue #2)

**Investigation already done (do not re-verify the whole chain — confirm only the file you change):**

The data layer is already complete in v1.1.0:

- `src/store.ts` line ~37–45: `HotkeyBindings { toggle, gif, replay }`, default `replay: "F8"`, persisted under `KEY_HOTKEY_BINDINGS` via `writeHotkeyBindings`.
- `src/App.tsx` line ~117–122: `registerHotkeys(hotkeysEnabled)` and `setHotkeyBindings(hotkeyBindings)` are pushed to main on change.
- `electron/main.ts` line ~518–588: `HotkeyBindings` mirror, `applyHotkeys()`, `tryRegister(activeHotkeys.replay, "replay")` already wired.
- `electron/preload.ts` line ~58–60: IPC exposes hotkey action `"toggle" | "gif" | "preview" | "replay"`.
- `src/App.tsx` line ~437–443: hotkey listener already handles `action === "replay"`.

**The actual gap:** `src/components/HotkeysDialog.tsx` line 12–15 — the `SLOTS` array only lists `toggle` and `gif`. The replay slot is missing from the UI even though the rest of the system already supports it.

**Minimal fix:** add one entry to `SLOTS`:

```ts
{ id: "replay", label: "Save instant replay", hint: "Saves the last N minutes from the replay buffer" }
```

Confirm the label/hint copy against the existing "Instant replay" section copy in `src/App.tsx` (search for `Instant replay` and `Save last`) — match the in-app wording so the dialog reads consistently. Adjust hint text if a closer match exists in the current UI strings.

**Do not** change `HotkeyBindings`, the store, the preload, or main.ts. The save handler in `HotkeysDialog.tsx` (`onSave(draft)`) already passes the full draft including `replay`. The App's `useEffect([hotkeyBindings])` already syncs it to main.

**Acceptance for A:**

1. Replay slot appears in the Customize Hotkeys dialog with the same rebind UX as toggle/gif.
2. Saving a rebinding persists across app restart.
3. New accelerator fires replay action; old one no longer does (single re-register via existing `applyHotkeys()` path).
4. Reset button restores replay to default `F8`.

### Sub-item B — Crop/replay timer state cleanup (Issue #4) — UI-state ONLY

**State surface (read-only — DO NOT REWRITE):**

- `src/store.ts`: `startedAt: number | null`, `elapsedMs: number`, `tickElapsed()` (`elapsedMs = Date.now() - s.startedAt`), `resetElapsed()` (sets both to null/0), `setRecording(id)` (sets `startedAt: Date.now()` and `elapsedMs: 0` when starting, clears both on null).
- `src/App.tsx` line ~124–128: interval `setInterval(() => tickElapsed(), 250)` gated on `status === "recording"`.

**Approach:**

1. Reproduce the issue first. Likely candidates to check (do not assume which one — observe):
   - Timer continuing or showing stale value after a replay save flow.
   - Timer showing nonzero before a recording fully starts (preparing → recording transition).
   - Timer not resetting after a cancelled crop selection (`beginCrop` → `setStatus("preparing")` → `setStatus("idle")`).
   - Double-tick if the interval effect somehow re-runs (check effect deps).
2. If the symptom is **clearly** at the UI-state level (a missed `resetElapsed`, a wrong gating condition on the interval effect, a stale closure on `startedAt`), apply the smallest possible fix in `src/App.tsx` and/or `src/store.ts`.
3. If the symptom traces below the UI state — i.e. into capture lifecycle, MediaRecorder, recorder-client, recorder.ts, or anything that requires touching the capture pipeline — **STOP**. Document the exact symptom, the exact path, and where the UI-state-only fix would be insufficient. Defer the deeper fix to T-008 (v2 integration). This is per the planning-session scope decision.

**Acceptance for B (loose, by design — this is a "maybe" item):**

- No regression vs v1.1.0 timer behavior in any of: normal screen record, window record, crop record, replay buffer running with no active recording, replay save.
- If a fix is applied: the symptom, the diff, and the verification steps are written into the implementation-session handover.
- If no fix is applied: the implementation-session handover documents what was checked and why it was deferred.
