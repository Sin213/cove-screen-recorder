### Classification

**Validation-policy / validation-logic gap on the EXPORTING-window length assumption.** The VAL-UI-003 gate at `validation/drivers.ts:5123–5128` requires the EXPORTING phase to be ≥ 3 wall-clock seconds so that HUD-Hz can be sampled across the window. The threshold is structurally incompatible with the speed of the stream-copy export path that is the default.

This is **not**:

- a duplicate-PTS regression (`duplicatedPtsCount` invariant is owned by VAL-EXP-010, which passed)
- a source/runtime regression of the helper/encoder/export pipeline (`export.completed` is emitted correctly, file is valid, SHA256-verified, file plays)
- a capture-instability symptom (capture didn't run during this row; VAL-UI-003 only touches the export pipeline)
- a regression of `9356569` (the patch under test only touched VAL-EXP-010 cadence policy, not VAL-UI-003)

It **is**:

- a **validation-policy mismatch**: VAL-UI-003 was scoped against a slower-export assumption (full-mux re-encode-style) but the default helper export path is `mode = stream-copy`, which is wall-clock-dominated by file-size copy, not by frame-decode/encode wall-clock.
